# 发布、安装与代码签名说明

## 1. 构建

在项目根目录运行：

```bat
build_exe.bat
```

生成 `dist\底稿未完成助手\底稿未完成助手.exe`。程序必须以文件夹形式分发，`_internal` 不能省略。

生成带安装脚本和压缩包的发布版本：

```bat
build_release.bat
```

输出：

```text
release\底稿未完成助手-0.3.0\
release\底稿未完成助手-0.3.0.zip
```

如已生成 Inno Setup 安装包，`build_release.bat` 还会把
`release\底稿未完成助手-0.3.0-安装程序.exe` 一并放入发布目录和压缩包。

## 2. 按用户安装

发布包内提供四种方式：

- **`安装程序.exe`**：双击图形化安装，复制程序到当前用户目录并创建开始菜单快捷方式；
- **`底稿未完成助手-0.3.0-安装程序.exe`**：Inno Setup 6 标准安装包，按向导安装；
- `安装.bat` / `install_per_user.ps1`：PowerShell 脚本安装；
- `installer.iss` / `build_inno.bat`：在已安装 Inno Setup 6 的机器上重新生成标准安装包。

默认安装到：

```text
%LOCALAPPDATA%\Programs\底稿未完成助手
```

不需要管理员权限。程序数据仍保存在 `%LOCALAPPDATA%\WorkpaperTodo`，安装和卸载默认不删除数据。

`安装程序.exe` 会：

1. 检查程序是否正在运行；
2. 复制程序文件夹；
3. 写入卸载脚本；
4. 创建“底稿未完成助手”和“卸载底稿未完成助手”开始菜单快捷方式；
5. 可选启动程序。

卸载：

- 开始菜单“卸载底稿未完成助手”；
- 或运行 `卸载.bat` / `uninstall_per_user.ps1`；
- 或 `安装程序.exe --uninstall`。

如确认不再需要事项数据，追加 `-RemoveData`（或 `--remove-data`）。该参数会删除 `%LOCALAPPDATA%\WorkpaperTodo`，请先备份。

### Inno Setup 6

`installer.iss` 已按“当前用户安装、无需管理员权限”编写。当前构建环境已安装
Inno Setup 6（`C:\Program Files (x86)\Inno Setup 6\`），并已生成：

```text
release\底稿未完成助手-0.3.0-安装程序.exe
```

重新生成时运行：

```bat
build_inno.bat
```

`build_inno.bat` 会先在 `PATH` 中查找 `iscc`，找不到时回退到 Inno Setup 6 的默认安装目录。该脚本与 `安装程序.exe` 使用相同的程序目录和数据目录约定。

已对 0.3.0 Inno 安装包做静默安装和卸载验证：安装到临时目录、开始菜单快捷方式创建、卸载器删除程序目录和快捷方式、卸载后不删除 `%LOCALAPPDATA%\WorkpaperTodo` 数据；并另用 explorer 普通权限令牌验证了按用户安装和快捷方式清理。安装包当前未签名，正式分发前仍需按第 3 节补受信任签名。

## 3. 代码签名

当前交付的 exe **未使用受信任证书签名**，原因是当前环境没有可用的代码签名证书。本机证书库中只有一个自签名 VSTO 开发证书（`CN=Xiaowen Office VSTO Development`，根证书不受信任），不能用于正式分发。因此 Windows SmartScreen 仍可能提示“未知发布者”。

已提供签名脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools\sign_exe.ps1 `
  -Exe "dist\底稿未完成助手\底稿未完成助手.exe" `
  -Pfx "证书.pfx" -Password "证书密码"
```

脚本优先使用 `signtool`，找不到时回退到 PowerShell Authenticode。签名后会验证 `SignatureType` 和证书链状态。

已用临时自签名证书验证签名流程：

- `SignatureType=Authenticode`；
- 证书主题和签名者写入成功；
- `Status=UnknownError` 是根证书不受信任的预期结果；
- 临时证书和测试副本在验证后删除。

自签名证书**不能**替代正式代码签名证书，也不会消除 SmartScreen 警告，因此没有把自签名结果作为正式发布包。正式分发前需要事务所提供受信任的代码签名证书（通常需要 EV 证书或内部白名单），然后重新签名并计算 SHA256。

签名前请确认：

- 证书用途包含代码签名；
- 时间戳服务可访问；
- 签名后在 Windows 10/11 上重新做一次 SmartScreen 和启动验证；
- 事务所 IT 是否要求 EV 证书或内部白名单。

不要把证书或密码写入项目文件，也不要把自签名证书分发给最终用户要求其信任。

## 4. 版本与校验

- 版本号：`workpaper_todo/__init__.py` 中的 `__version__`。
- 发布脚本会输出 exe、图形化安装程序、Inno 安装包和 zip 的 SHA256。
- 分发时请同时提供 zip 的 SHA256，便于接收方核对完整性。
- 升级前请保留上一版本目录；数据目录与程序目录分离，升级程序不会覆盖事项数据。

## 5. 回滚

1. 退出程序；
2. 用上一版本程序目录替换当前程序目录；
3. 数据文件如已由新版本迁移，回滚到旧版本前请先备份 `data.db`，并确认旧版本能读取当前数据库版本。程序遇到较新数据库会拒绝启动，避免损坏数据。
