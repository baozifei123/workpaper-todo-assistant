# Excel / WPS 加载项方案评估

## 1. 结论

当前版本继续使用“独立 exe + NativeOM”作为主力方案，不在 0.2.0 中重写为加载项。加载项更适合在本工具经过一段时间真实使用、确认日常摩擦仍然明显后，做小范围试点。

原因：

- 独立 exe 已经同时支持 Excel 和 WPS，且无需在两套加载项体系里分别适配；
- 加载项会引入签名、宏安全、IT 白名单、升级分发等额外成本；
- 事务所对加载项和宏的安全策略通常比普通桌面程序更严格；
- 当前最大的体验问题（登记、定位、状态管理）已经可以在独立 exe 中解决。

## 2. 可选方案对比

| 方案 | Excel | WPS | 优点 | 主要成本/风险 |
|---|---|---|---|---|
| 独立 exe + NativeOM（当前） | 支持 | 支持 | 一套代码、无需加载项权限、部署简单 | 依赖窗口前台/句柄；手动按钮需切回程序；不能完全消除焦点问题 |
| Excel VSTO/COM 加载项 | 支持 | 不支持 | 原生 Ribbon、直接读取 Selection、体验最好 | .NET/VSTO 部署、签名、IT 白名单；WPS 需另做 |
| Office JS 加载项 | 支持 | 部分 | 跨平台、可任务窗格、更新方便 | 需要 Office/WebView 环境、清单托管、企业部署策略；对本地大文件/宏文件支持有限 |
| WPS JS 加载项 | 不支持 | 支持 | WPS 原生 Ribbon/任务窗格 | 与 Excel 方案不通用；WPS 版本与加载项规范差异 |
| VBA 个人宏/加载宏 | 支持 | 部分 | 开发快、可直接用 Selection | 宏安全策略、分发困难、WPS 兼容性不稳定；不适合作为正式产品 |

## 3. 推荐的试点形态

如果后续决定试点，建议先做“薄加载项”，不要重写全部功能：

1. 在 Excel/WPS 中增加一个 Ribbon 按钮“登记当前单元格”；
2. 任务窗格只显示当前项目、最近登记和未完成数量；
3. 真正的清单、筛选、历史、备份仍由独立 exe 负责；
4. 加载项通过本机 IPC（命名管道或本地 HTTP + 仅回环地址）把“文件、工作表、单元格、内容快照”交给 exe；
5. 不把底稿内容发送到任何远程服务。

这样即使加载项在某个 Excel/WPS 版本上不可用，独立 exe 仍可继续使用。

## 4. 试点前需要确认

- 事务所 IT 是否允许加载项、宏和本地回环 IPC；
- Excel 版本（Microsoft 365 / 2019 / 2021）和 WPS 版本范围；
- 是否能提供代码签名证书和加载项清单托管地址；
- 加载项升级、回滚和白名单流程；
- 客户底稿是否允许加载项读取单元格内容（仍然只在本机处理）。

## 5. 本版本决定

- 不开发加载项；
- 保留独立 exe 为主力；
- 在 `docs/兼容性验证记录.md` 中记录当前验证边界；
- 等真实使用反馈表明“登记/定位步骤仍然太多”时，再启动试点评估。
